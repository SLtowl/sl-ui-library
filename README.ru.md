# SL UI Library

[English](README.md) · [Русский](README.ru.md)

Плагин для ИИ-ассистентов и библиотека интерактивных UI-компонентов с экспортом в HTML, CSS, JavaScript, React и Next.js.

**Версия 1.2.2** публикует обновлённый сайт библиотеки, проверенные автором исправления взаимодействий, экспорт кода и ZIP с выбранной палитрой и настройку Hermes Agent. В ней сохранены все 388 компонентов и адаптеры React / Next.js, использующие исходные контроллеры, наряду с HTML, CSS и JavaScript. [Описание обновления](docs/releases/v1.2.2.md) · [Интеграция с фреймворками](docs/frameworks.md) · [Предыдущее обновление](docs/releases/v1.2.1.md).

![Графитовые элементы SL UI Library в тёплой студийной композиции](docs/media/cover.png)

**388 интерактивных компонентов** и 390 вариантов экспорта. Обычные HTML/CSS/JavaScript-версии не требуют сторонних библиотек во время работы, удалённых шрифтов или готовых наборов иконок. Версии React и Next.js используют среду соответствующего фреймворка в вашем приложении и подключают тот же исходный контроллер как изолированный клиентский виджет. Компоненты можно попробовать на сайте и скачать со всеми исходными файлами.

## Установка плагина

Установка выполняется напрямую из этого GitHub-репозитория. Наличие плагина в официальном каталоге и аккаунт библиотеки не требуются.

### Claude Code

Вставьте эту строку в терминал, где установлен Claude Code:

```sh
claude plugin marketplace add SLtowl/sl-ui-library && claude plugin install sl-ui-library@sl-ui-library
```

Внутри чата Claude Code выполните те же действия двумя slash-командами:

```text
/plugin marketplace add SLtowl/sl-ui-library
/plugin install sl-ui-library@sl-ui-library
```

### Codex

Вставьте эту строку в терминал, где установлен Codex:

```sh
codex plugin marketplace add SLtowl/sl-ui-library && codex plugin add sl-ui-library@sl-ui-library
```

Команды в одну строку работают в оболочках macOS/Linux, Windows Command Prompt и PowerShell 7+. В Windows PowerShell 5 выполните две команды отдельно; продолжайте только после успешного завершения первой. Они регистрируют репозиторий и устанавливают плагин через собственный менеджер плагинов приложения. Они не устанавливают само ИИ-приложение и не копируют кнопки в ваши проекты.

После установки начните новую задачу. Затем можно попросить, например:

> Добавь кнопку «Нравится» из SL UI Library. Сделай фиолетовый фон и светлый текст, сохрани анимацию и управление с клавиатуры.

Ассистент выбирает компонент, читает его исходный код и инструкции для выбранного формата, затем экспортирует полный пакет с нужной палитрой. Файлы HTML, CSS, JavaScript, React и Next.js включены для каждого варианта. После установки весь каталог и исходные файлы доступны офлайн; требования самого ИИ-приложения к подключению остаются отдельными. Для встроенного инструмента командной строки нужен Node.js 22+.

### Hermes Agent

Подключите существующий skill `use-sl-ui` через внешние папки skills в Hermes. На машине, где работает агент, должны быть установлены Hermes Agent, Git и Node.js 22+.

Клонируйте этот репозиторий в постоянную папку:

```sh
git clone https://github.com/SLtowl/sl-ui-library.git
```

В `config.yaml` активного профиля Hermes (`~/.hermes/config.yaml` для профиля по умолчанию) добавьте папку skills из клонированного репозитория:

```yaml
skills:
  external_dirs:
    - /absolute/path/to/sl-ui-library/plugins/sl-ui-library/skills
```

Замените пример своим абсолютным путём. На Windows используйте прямые слеши, например `C:/Tools/sl-ui-library/plugins/sl-ui-library/skills`. Если раздел `skills` уже есть, дополните его, сохранив остальные папки.

Перезапустите Hermes, затем в новом разговоре введите `/use-sl-ui` и опишите задачу для интерфейса. Сохраните репозиторий целиком: skill находит инструменты и офлайн-исходники относительно своей папки. Копирования одного `SKILL.md` недостаточно. Этот способ подключает skill; размещение в каталоге плагинов Hermes не требуется.

[Официальная документация внешних папок skills в Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills#external-skill-directories) · [Подробная настройка](docs/agents.md#hermes-agent)

### Claude и ChatGPT без терминала

**Claude:** [скачайте ZIP плагина](https://sltowl.github.io/sl-ui-library/downloads/sl-ui-library-plugin.zip) и загрузите пользовательский плагин через **Customize → Plugins**, если ваш клиент поддерживает такую возможность.

**ChatGPT в браузере:** команды выше не устанавливают плагин в обычный чат. Публичная ссылка Install для ChatGPT пока недоступна; размещение в официальном каталоге планируется отдельно. Для установки в Codex такая публикация не требуется.

[Настройка платформ, поддерживаемые клиенты и обновления](docs/agents.md) · [Документация плагинов Claude Code](https://code.claude.com/docs/en/discover-plugins) · [Документация плагинов OpenAI](https://developers.openai.com/plugins/build/plugins)

<details>
<summary>Нужен только один компонент?</summary>

В скачанном репозитории выполните:

```sh
node component.mjs like ./my-button
```

Команда экспортирует один полный пример в новую папку. Родительская папка должна существовать; запись в существующую папку и использование родительских папок-символических ссылок запрещены. Перед записью исходные файлы проверяются.

</details>

## Обновление плагина

Если плагин уже установлен через GitHub-маркетплейс, выполняйте следующие команды в терминале по одной. Продолжайте только после успешного завершения первой команды.

**Codex:**

```sh
codex plugin marketplace upgrade sl-ui-library
codex plugin add sl-ui-library@sl-ui-library
```

**Claude Code:**

```sh
claude plugin marketplace update sl-ui-library
claude plugin update sl-ui-library@sl-ui-library
```

Если плагин в Claude Code установлен с областью действия project или local, добавьте соответствующий параметр `--scope project` или `--scope local` к команде обновления плагина. После обновления начните новую сессию. Если вы устанавливали плагин загрузкой ZIP, скачайте актуальный [архив плагина](https://sltowl.github.io/sl-ui-library/downloads/sl-ui-library-plugin.zip) и замените его через менеджер плагинов приложения.

### Версии и проверка обновлений

**Hermes Agent:** просмотрите изменения в репозитории, затем выполните `git -C "/absolute/path/to/sl-ui-library" pull --ff-only` для подключённой выше копии и перезапустите Hermes. Подставьте свой путь к репозиторию. Обновляется подключённая библиотека, а не компоненты, ранее экспортированные в ваши приложения.

Пакет репозитория, переносимый манифест, манифесты Claude/Codex и встроенный каталог используют один номер версии. Каждое опубликованное изменение кода плагина должно повышать версию: одного push в GitHub недостаточно для кешей, учитывающих версии. Версия 1.2.2 обновляет проверенные исходники компонентов и сайт каталога. Версия 1.2.1 уточнила описания форматов для таких клиентов. Ранее версия 1.1.2 добавила более строгую проверку соответствия исходникам.

[Определение версий в Claude Code](https://code.claude.com/docs/en/plugin-marketplaces#version-resolution-and-release-channels) · [Команды маркетплейса Codex](https://developers.openai.com/plugins/build/plugins).

Проверка исходников сопоставляет классы `sl-*` и геометрию встроенных SVG в сериализованном HTML компонента. Она отмечает отсутствующие или изменённые маркеры исходников, но не обнаруживает произвольные ошибки CSS или анимации. Это явно запускаемая офлайн-проверка, а не фоновое наблюдение или автоматическое исправление. См. [руководство по проверке](plugins/sl-ui-library/scripts/integration-guide.md). При результате `needs-review` инструмент завершает работу с ненулевым кодом. Ассистент не должен утверждать, что интеграция SL UI выполнена, без полученных ID компонента, варианта, хешей исходников и успешно пройденной проверки.

Обновление плагина никогда не переписывает компоненты, уже скопированные в другое приложение.

### Обновления каталога

Для канала релизов подготовлен необязательный механизм обновления данных. После публикации канала и включения пользователем он сможет проверять наличие нового каталога при использовании, не чаще раза в день, с офлайн-режимом на случай недоступности сети. Уже добавленные в ваше приложение компоненты никогда не заменяются незаметно. Обновления кода и навыка плагина по-прежнему выполняет ИИ-приложение.

**Статус обновлений:** публичный канал обновлений данных пока не запущен. Телеметрия отключена. Для владельца есть локальный инструмент подсчёта скачиваний файлов релизов, а не трекер; такие скачивания не равны уникальным установкам. См. [подробности об обновлениях и статистике](docs/agents.md).

## Интеграция компонентов

Каждый архив компонента включает версии HTML, CSS, JavaScript, React и Next.js, примеры интеграции и локальные ресурсы. В разделе Usage описано, как добавить компонент в проект и подключить обработчики действий.

### Выбор формата экспорта

| Формат | Файлы для подключения | Интеграция |
| --- | --- | --- |
| HTML, CSS и JavaScript | `index.html`, `buttons.css`, `buttons.js`, `example.js` и необходимые локальные модули | Используйте исходный контроллер и подключите действия вашего приложения. |
| React | `Component.jsx` и `react-example.jsx` | Импортируйте адаптер, сохраняющий исходный компонент, и определите обработчики в вашем приложении. |
| Next.js | `NextClient.jsx` и `next-page.jsx` | Используйте границу Client Component и пример с обработчиками, определяемыми на стороне приложения. |

Скачивайте полный ZIP. Версиям React и Next.js нужны `react-controller.mjs`, `react-font.mjs`, встроенный шрифт и другие вспомогательные ресурсы, указанные в документации. Копирование одного JSX-файла — не полная интеграция. Примеры и `framework-usage.md` описывают props, refs и жизненный цикл.

Версии React и Next.js — это изолированные адаптеры клиентских виджетов поверх исходных контроллеров, а не компоненты, заново переписанные на React-состояние. Начальный серверный вывод — стабильная заглушка, а не полноценный SSR интерфейса виджета. Учитывайте принадлежность полей форм, обработчики, CSP и интеграцию доступности в вашем приложении. Полный контракт приведён в [руководстве по фреймворкам](docs/frameworks.md).

Демонстрации архивирования, переименования и создания меняют только состояние превью. В рабочем приложении показывайте успех после успешного выполнения вашей реальной операции. Введённые пользователем имена остаются буквальным текстом, включая Unicode; подписи действий в компонентах остаются английскими.

## Сайт библиотеки

В репозитории находится вся статическая библиотека. Исходники хранятся на GitHub, а публичный сайт обслуживает GitHub Pages. Посетителям опубликованного сайта не нужны терминал или Node.js.

Сайт публикуется из `public/` через [Pages workflow](https://github.com/SLtowl/sl-ui-library/actions/workflows/pages.yml). Перед тем как делиться ссылкой, проверьте последнее развёртывание: если запуск завершился ошибкой, сайт не обновился.

<details>
<summary>Для разработчиков: запуск локальной копии</summary>

Требуется Node.js 22 или новее. В папке репозитория выполните:

```sh
npm start
```

Команда собирает экспорты и запускает локальный сервер. Откройте `http://127.0.0.1:4321/` на том же компьютере. Установка зависимостей не требуется. Используйте HTTP, а не открытие HTML-файла двойным щелчком.

</details>

## Структура репозитория

```text
public/                 Interactive site and component source
  packages/             Self-contained component examples
plugins/sl-ui-library/  Portable plugin, host manifests, skill and source tools
docs/                   Guides, studio photography and film
tests/                  Automated checks
install.mjs             Optional Codex CLI installer
component.mjs           Optional single-component export
```

`public/` содержит сайт и исходники компонентов, `packages/` — самостоятельные примеры. В `plugins/sl-ui-library/` находятся плагин, манифесты для ИИ-приложений, навык и инструменты работы с исходниками. `docs/` — руководства и медиаматериалы, `tests/` — автоматические проверки. `install.mjs` служит необязательной обёрткой установки через Codex CLI, `component.mjs` — инструментом экспорта одного компонента.

Редактируйте исходники компонентов в `public/packages/`, а метаданные — в `public/catalog-data.js`, затем запускайте `npm run build` и `npm run check`. Добавляйте в коммит исходники и отслеживаемые сгенерированные данные вместе. ZIP-архивы заново создаются при сборке или запуске, а не дублируются в истории Git. См. [правила внесения изменений](CONTRIBUTING.md).

## Проверки и ограничения

- Собственные SVG-иконки проекта и встроенные шрифты.
- Управление с клавиатуры, видимый фокус и поддержка уменьшенного движения.
- Проверки повторных взаимодействий и сброса состояния.
- Проверки согласованности исходников, ZIP-экспортов и пакета для ассистентов.
- Отсутствие скриптов аналитики и отслеживающих пикселей.

См. [результаты проверок и ограничения](QA.md). Релиз с поддержкой фреймворков 1.2.0 проверялся в Microsoft Edge на Chromium; Firefox, Safari и реальные сенсорные устройства требуют отдельной проверки релиза.
